Multi-agent commerce prototype

Shopping agents that can discover, negotiate and pay.

AgentCart explores autonomous commerce: a buyer agent compares offers across independent merchant agents, while deterministic checks keep checkout and payment within user-authorized limits.

Watch the demo ↓ Explore the code ↗

Built with Google ADK · A2A · ACP · AP2 · Razorpay Test Mode

From a shopping request to a bounded checkout.

The project connects several agentic-commerce ideas in one working prototype, with the payment decision kept outside the LLM's direct control.

One request. Multiple merchant agents.

The buyer agent discovers registered stores, requests structured proposals and compares the offers. Merchant agents represent UrbanKicks, ShoeKart and FastFeet, each with its own catalog and negotiation behaviour.

Google ADKA2A discoveryOffer negotiation

A2A · Agent discovery

Buyer and merchant agents exchange capabilities, product requests and structured proposals.

ACP · Checkout

Merchant checkout details are represented as a structured session with an authoritative total.

AP2 · Payment authority

Signed mandates bind a payment to an authorized amount, payee and checkout hash.

Deterministic policy

Python checks budget, merchant and buyer-side limits before the payment rail is called.

Razorpay Test Mode

Demonstrates order and payment flows using sandbox integration or local mock simulation.

WATCH objectives

Unfulfilled shopping intents can remain active and be re-evaluated when merchant events arrive.

How the flow works

A simplified view of the main path through the prototype.

  1. 1DescribeSet the item, preferences, delivery constraints and maximum budget.
  2. 2Discover & compareMerchant agents return offers; the buyer evaluates and negotiates.
  3. 3VerifyPolicy checks and AP2 mandate verification validate the checkout and payment authority.
  4. 4ExecuteRazorpay Test Mode or the local mock simulates the payment flow and records the result.

Prototype scope

AgentCart is an educational/demo project, not a production payment platform. Local mock payments do not move money. Mandate consumption, WATCH events, webhook idempotency and audit-chain state are process-local; they are not durable or distributed guarantees. Use sandbox credentials only, and never use this project for live customer payments.
